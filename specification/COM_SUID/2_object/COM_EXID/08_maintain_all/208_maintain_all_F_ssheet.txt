# NOTES:
# ------
  We don't return any value representing how many objects were updated
  (this information is logged, when log level is DEBUG).

    Reason:
    -------
    object in game may have damage diff to value stored in database
    (sync hasn't happened yet) and also MySQL will skip rows, which
    doesn't have `ow_damage` > 0.0.

    That means, there is no point to compare number of processed
    objects for update due to above reasons. However - everything
    will work as expected:
    1. SQF will set damage to 0.0 where current damage is > 0.0;
    2. MySQL will take `ow_bid` (base ID) and updates all binded
       object damage to 0.0.
    As a result, at the end of maintainance all objects in-game
    and in the database will have the same value.
