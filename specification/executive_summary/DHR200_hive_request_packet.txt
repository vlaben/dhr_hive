# [A] NAMING CONVENTION:
# -------------------------------------------------------- |

  COM_SUID : system element unique ID
  COM_TYPE : type of request
  COM_EXID : execution id
  COM_ARGV : argument vector



# [B] PACKET REQUIRED STRUCTURE:
# -------------------------------------------------------- |

  + ---------------------------------------------------------- |
  |             HEADER             |          PAYLOAD          |
  + ------------------------------ + ------------------------- |
  | COM_SUID | COM_TYPE | COM_EXID | COM_ARGV[ARG1,[...,]ARGN] |
  + ---------------------------------------------------------- |
                         (max packet size : 10 x 1'024 = 10KB)

  + ------------------------------------------------- +
  |                 |               repr              |
  |                 |         (flat signature)        |
  |                 + ------------------------------- |
  |                 |   (                             |
  |                 |       i,                        | HEADER  : COM_SUID
  |                 |       i,                        |           COM_TYPE
  |   Packet:       |       i,                        |           COM_EXID
  |   -------       |       a                         | PAYLOAD : COM_ARGV[ARG1,[...,]ARGN]
  |   [             |   )                             |
  |       6,        + ------------------------------- +
  |       1,        |               repr              |
  |       1,        |      (recursive signature)      |
  |       [         + ------------------------------- |
  |          true,  |                                 |
  |          ...    |   (                             |
  |       ]         |       i,                        | HEADER  : COM_SUID
  |   ]             |       i,                        |           COM_TYPE
  |                 |       i,                        |           COM_EXID
  |                 |       (                         | PAYLOAD : COM_ARGV[
  |                 |           b,                    |             ARG1,
  |                 |           ...                   |             ...
  |                 |       )                         |           ]
  |                 |   )                             |
  + ------------------------------------------------- +

# [B1/2] HEADER: COM_TYPE:
# -------------------------------------------------------- |

  + ------------------------------------------------------------------------- + ------------------------------------------------------------------------- +
  |                  (DHR hive request packet specification)                  |                 (DHR hive response packet specification)                  |
  |                                    REQUEST                                |                                   RESPONSE                                |
  + ------------------------------------------------------------------------- + ------------------------------------------------------------------------- +
  | COM_TYPE    | value   | description                                       | response size | COM_EXID success             | <?> failure                |
  + ----------- + ------- + ------------------------------------------------- + ------------- + ---------------------------- + -------------------------- +
  |             |         | SYNC call type.                                   | 3             |                              |                            |
  |             |         |                                                   |               |                              |                            |
  | auth        | 1       | System packets controlling interaction            |               | [1,0,"DATA"]                 | COM_EXID failure:          |
  |             |         | with dhr_hive[_d].dll.                            |               |                              | -----------------          |
  |             |         | Guarded, strictly handled by the rules.           |               |                              | [1,1,"DATA"]               |
  |             |         |                                                   |               |                              |                            |
  |             |         |                                                   |               |                              | hive RESPONSE failure:     |
  |             |         |                                                   |               |                              | ----------------------     |
  |             |         |                                                   |               |                              | [1,2,"err_INVALID"]        |
  |             |         |                                                   |               |                              | [1,2,"err_RESSIZE"]        |
  |             |         |                                                   |               |                              |                            |
  |             |         | On fail auth, all subsequent packets              |               |                              | hive SYSTEM failure:       |
  |             |         | are blocked (Arma2OA server will always           |               |                              | --------------------       |
  |             |         | receive "err_REVOKED" response on each            |               |                              | [1,3,"err_ABORTED"]        |
  |             |         | subsequent call).                                 |               |                              | [1,3,"err_REVOKED"]        |
  + ----------- + ------- + ------------------------------------------------- + ------------- + ---------------------------- + -------------------------- +
  |             |         | Execute call type.                                | 3             |                              |                            |
  |             |         |                                                   |               |                              |                            |
  | execute     | 2       | Generally, request dispatcher to the target       |               | [2,0,"DATA"]                 | COM_EXID failure:          |
  |             |         | background worker thread (without tracking).      |               | [2,0,""]                     | -----------------          |
  |             |         |                                                   |               |                              | [2,1,"DATA"]               |
  |             |         | Since packet from Arma2OA server is always        |               |                              |                            |
  |             |         | deserialized and validated, caller should         |               |                              | hive RESPONSE failure:     |
  |             |         | always inspect at least RES_CODE                  |               |                              | ----------------------     |
  |             |         | (even on success).                                |               |                              | [2,2,"err_INVALID"]        |
  |             |         |                                                   |               |                              | [2,2,"err_RESSIZE"]        |
  |             |         | Call is very fast - once validation               |               |                              |                            |
  |             |         | is succcessfully done, packet is (mostly) passed  |               |                              | hive SYSTEM failure:       |
  |             |         | to the target COM_SUID and enqueued to the worker |               |                              | --------------------       |
  |             |         | thread queue, hence main thread blocking is       |               |                              | [2,3,"err_ABORTED"]        |
  |             |         | minimal (non significant).                        |               |                              | [2,3,"err_REVOKED"]        |
  + ----------- + ------- + ------------------------------------------------- + ------------- + ---------------------------- + -------------------------- +
  |             |         | ASYNC call type.                                  | 4             |                              |                            |
  |             |         |                                                   |               |                              |                            |
  | promise     | 3       | Creates promise, stores future and returns        |               | [3,0,PRID,"DATA"]            | COM_EXID failure:          |
  |             |         | back to the caller without blocking the main      |               | [3,0,PRID,""]                | -----------------          |
  |             |         | thread. Caller will receive unique promise ID     |               |                              | [3,1,PRID,"DATA"]          |
  |             |         | (PRID), which will be used for the next call,     |               |                              |                            |
  |             |         | when future result is required.                   |               |                              | hive RESPONSE failure:     |
  |             |         |                                                   |               |                              | ----------------------     |
  |             |         |                                                   |               |                              | [3,2,PRID,"err_INVALID"]   |
  |             |         |                                                   |               |                              | [3,2,PRID,"err_RESSIZE"]   |
  |             |         |                                                   |               |                              |                            |
  |             |         |                                                   |               |                              | hive SYSTEM failure:       |
  |             |         |                                                   |               |                              | --------------------       |
  |             |         |                                                   |               |                              | [3,3,PRID,"err_ABORTED"]   |
  |             |         |                                                   |               |                              | [3,3,PRID,"err_REVOKED"]   |
  + ----------- + ------- + ------------------------------------------------- + ------------- + ---------------------------- + -------------------------- +
  |             |         | Part of ASYNC call type.                          | 5             |                              |                            |
  |             |         |                                                   |               |                              |                            |
  | future      | 4       | Looks up the future result using unique           |               |                              |                            |
  |             |         | PRID as received from promise request COM_TYPE.   |               |                              |                            |
  |             |         |                                                   |               |                              |                            |
  |             |         | If response is not ready yet, caller receives     |               | result not available yet:    | COM_EXID failure:          |
  |             |         | signal (RES_CODE = -1) to repeat request later.   |               | -------------------------    | -----------------          |
  |             |         |                                                   |               | [4,-1,PRID,0,""]             | [4,1,PRID,0,"DATA"]        |
  |             |         |                                                   |               |                              |                            |
  |             |         | When invalid PRID is received, a special          |               |                              | invalid PRID:              |
  |             |         | RESPONSE is sent back to the caller,              |               |                              | -------------              |
  |             |         | where PRID == 0 signals the fact.                 |               |                              | [4,1,0,0,""]               |
  |             |         |                                                   |               |                              |                            |
  |             |         | All responses having RES_QUID = 0 (no msgs left)  |               | single packet result:        | hive RESPONSE failure:     |
  |             |         | are considered complete single packet result.     |               | ---------------------        | ----------------------     |
  |             |         |                                                   |               | [4,0,PRID,0,"DATA_0"]        | [4,2,PRID,0,"err_INVALID"] |
  |             |         |                                                   |               |                              | [4,2,PRID,0,"err_RESSIZE"] |
  |             |         | All responses having RES_QUID > 0 (msgs left)     |               | multi packet result:         |                            |
  |             |         | are considered multi packet result                |               | --------------------         | hive SYSTEM failure:       |
  |             |         | and concrete RES_QUID value represents            |               | [4,0,PRID,2,"DATA_0"]        | --------------------       |
  |             |         | the answer to the question:                       |               | [4,0,PRID,1,"DATA_1"]        | [4,3,PRID,0,"err_ABORTED"] |
  |             |         | "HOW MANY TIMES SHOULD I SENT FUTURE COM_TYPE     |               | [4,0,PRID,0,"DATA_2"]        | [4,3,PRID,0,"err_REVOKED"] |
  |             |         |  REQUEST TO RECEIVE COMPLETE RESPONSE?"           |               |                              |                            |
  + ----------------------------------------------------------------------------------------------------------------------------------------------------- +



# [B1/3] HEADER: COM_EXID:
# -------------------------------------------------------- |

  + --------------------------------------------- +
  |          Each COM_SUID has available          |
  |          31 unique execution ID calls         |
  + --------------------------------------------- +
  | COM_SUID           | COM_EXID available range |
  + ------------------ + ------------------------ +
  | controller         |                          |
  | ------------------ |                          |
  | control            |                          |
  | ------------------ |                          |
  | server             |       <1*, 31>**         |
  | ------------------ |                          |
  | player             |                          |
  | ------------------ |                          |
  | object             |                          |
  | ------------------ |                          |
  | vehicle            |                          |
  + --------------------------------------------- +

  *  COM_EXID 0 is reserved for internal purposes, hence 31 calls instead of 32.

  ** 31* unique COM_EXID calls per COM_SUID / 186 (6 * 31) per whole system
     is more then enough to satisfy DayZ Epoch requirements.
     If there is ever need to increase this value, it is possible to replace
     32 bit bitmask with 64 bit bitmask in source code, which would allow 63*
     unique COM_EXID calls / 378 (6 * 63) (source code update would be required).
