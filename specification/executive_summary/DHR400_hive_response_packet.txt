# [A] NAMING CONVENTION:
# -------------------------------------------------------- |

  RES_TYPE : type of response
  RES_CODE : response return code
  RES_PRID : promise id
  RES_QUID : response queue id
  RES_DATA : response data



# [B] PACKET REQUIRED STRUCTURE:
# -------------------------------------------------------- |

               + ---------------------------------------------------- +
               |        HEADER       |            PAYLOAD             |
               | ------------------- + ------------------------------ |
               |    1     |    2     |    3     |    4     |    5     |
  + --------- ++ -------- + -------- + -------- + -------- + -------- ++ ------------- +
  | COM_TYPE  || RES_TYPE | RES_CODE | RES_PRID | RES_QUID | RES_DATA || response size |

# [B1/1] HEADER: RES_TYPE:
# -------------------------------------------------------- |

  Related specification:
  ----------------------
  DHR200_hive_request_packet.txt

  + type of response
  + MUST match related request COM_TYPE
  + std::size_t

  + --------------------- +
  | COM_TYPE    | value   |
  + ----------- + ------- +
  | auth        |   1     |
  | ----------- + ------- |
  | execute     |   2     |
  | ----------- + ------- |
  | promise     |   3     |
  | ----------- + ------- |
  | future      |   4     |
  + --------------------- +



# [B1/1] HEADER: RES_CODE:
# -------------------------------------------------------- |

  + response return code
  + int

  + ------------------------------------------------------------------------------------------------------------- +
  | CODE    | meaning                | is static response     | description                                       |
  + ------- + ---------------------- + ---------------------- + ------------------------------------------------- +
  | -1      | awaiting response      | YES                    | COM_EXID execution result is enqueued -           |
  |         | COM_TYPE future only   |                        | result is not available yet. Try again later.     |
  + ------- + ---------------------- + ---------------------- + ------------------------------------------------- +
  |  0      | COM_EXID success       | NO                     | COM_EXID execution finished with a success.       |
  |         |                        | may have runtime msg   |                                                   |
  + ------- + ---------------------- + ---------------------- + ------------------------------------------------- +
  |  1      | COM_EXID failure       | NO                     | COM_EXID execution finished with an error.        |
  |         |                        | has runtime err msg    |                                                   |
  + ------- + ---------------------- + ---------------------- + ------------------------------------------------- +
  |  2      | response failure       | YES                    | There are 2 main reasons, why response failure    |
  |         |                        |                        | may be encountered:                               |
  |         |                        |                        | -------------------                               |
  |         |                        | "err_RESSIZE"          | [1][ likely] multipacket response is NOT          |
  |         |                        |                        |              supported for given RES_TYPE         |
  |         |                        |                        |              and current response exceeds         |
  |         |                        |                        |              max response size limit.             |
  |         |                        |                        | -------------------                               |
  |         |                        | "err_INVALID"          | [2][unlikely] internal response pointer is        |
  |         |                        |                        |               not valid - this is INTERNAL        |
  |         |                        |                        |               matter having role during devop     |
  |         |                        |                        |               and shouldn't exist in prod.        |
  + ------- + ---------------------- + ---------------------- + ------------------------------------------------- +
  |  3      | system (FATAL) failure | YES                    | Access to DHR hive system is revoked.             |
  |         |                        |                        | The server owner MUST process following steps:    |
  |         |                        | "err_ABORTED"          | [1] STOP server                                   |
  |         |                        | "err_REVOKED"          | [2] read logs                                     |
  |         |                        |                        | [3] fix the issue (fix error; ban skid; ...)      |
  |         |                        |                        | [4] START server                                  |
  + ------------------------------------------------------------------------------------------------------------- +



# [B2/1] PAYLOAD: RES_PRID:
# -------------------------------------------------------- |

  + promise id
  + std::size_t

  + ------------------------------------------------------ +
  | PRID     | description                                 |
  + -------- + ------------------------------------------- +
  |   0      | invalid promise ID                          |
  + -------- + ------------------------------------------- +
  | > 0      | valid promise ID                            |
  + ------------------------------------------------------ +



# [B2/2] PAYLOAD: RES_QUID:
# -------------------------------------------------------- |

  + response queue id
  + std::size_t

  + ------------------------------------------------------------------------------------ +
  | QUID    | description                                                                |
  + ------- + -------------------------------------------------------------------------- +
  |   0     | response is complete (0 msgs left)                                         |
  + ------- + -------------------------------------------------------------------------- +
  | > 0     | current response queue ID, where ID may be translated to "msgs left"       |
  + ------------------------------------------------------------------------------------ +



# [B2/3] PAYLOAD: RES_DATA:
# -------------------------------------------------------- |

  + response data
  + serialized output SQF data structure to be
    deserialized in Arma2OA server context
